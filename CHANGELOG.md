# Changelog

## 0.1.2 — 2026-11-27

- All seven methods share an early review of requirements and linked decisions. When a material gap remains, ask a concrete question and keep the affected verdict open while independent checks continue.
- Reopen affected acceptance criteria after a change or clarification. Keep previously verified evidence for independent behavior.
- Eight development cases cover linked requirements, missing placement, conflicting or superseded sources, changed retry expectations, smoke testing without a specification, and both drafted and authorized mock questions.

## 0.1.1 — 2026-11-15

- Shared adaptive decisions are available from all seven methods, without requiring an extra loop for a straightforward verified result.
- Stronger event-time configuration/identity checks, preservation of the requested actor and scope, and recovery from stale or truncated method reads.
- Optional async/media investigation separates runner counts, attempts, connection, heard content and durable results while retaining proactive human journeys.
- Development-only behavioral packet preparation and adjudication binding keep outcome, adherence and observed loading separate; they do not automatically judge semantic truth.
- Package-test fixtures use declared current source bytes, preserving unlisted author assets without weakening the release allowlist.

## 0.1.0

First public version of Outcome QA.

- Seven QA methods: test design, exploration, automation, AI quality, checker audit, retest and feature security.
- Adaptive exploratory testing: choose the next check from the evidence, use relevant tools and methods, and bring in independent review when it helps.
- Human journeys, realistic inputs, recovery and repeat actions, cross-layer diagnosis and independent outcome checks.
- Optional reviewers and local helpers for state contracts, evidence records, project routing and playbook export.
- One-command Agent Skills installation for multiple hosts, a clone-based full plugin for Codex and Claude Code, and a Markdown playbook fallback.
- Separate install bundle and source tree. The source keeps tests, CI and runnable synthetic demos; the install bundle carries only runtime material.

See [installation](distribution/INSTALL.md), [demo](docs/DEMO.md), and [verification](docs/VERIFICATION.md).
